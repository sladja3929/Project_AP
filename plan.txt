#### 2-4. bIsReleased 의미 유지 (answer.txt 피드백)

- `BufferInputInternal()`에서 릴리즈 상태 저장
- `ActivateAbilityByTag()`에서 `bBufferActionReleased = bServerBufferActionReleased`로 반영
- 기존 ActivateAbility의 EventMagnitude 로직 유지

#### 2-5. TTL/그레이스 정책

- `TMap<FGameplayTag, FPendingInput> PendingInputs`: 태그별 마지막 입력만 유지 (덮어쓰기)
- `InputGracePeriod = 0.1f`: 100ms 그레이스 기간
- hold-release는 수신 즉시 서버 홀드셋에서 제거 (버퍼 상태와 무관)

### 3. 어빌리티 커브 폴링 적용

#### 3-1. ActionRecoveryAbility 수정 (모든 자식 어빌리티에 적용됨)
**파일**: `Source/ActionPractice/Public/GAS/Abilities/Player/ActionRecoveryAbility.h/cpp`

**추가된 상수**:
- `CurveName_EnableBufferInput = TEXT("EnableBufferInput")`
- `CurveName_ActionRecovery = TEXT("ActionRecovery")`

**커브 폴링 활성화** (`BindEventsAndReadyMontageTask()`):
```cpp
TArray<FName> CurveNames;
CurveNames.Add(CurveName_EnableBufferInput);
CurveNames.Add(CurveName_ActionRecovery);
PlayMontageWithEventsTask->EnableCurvePolling(CurveNames);
PlayMontageWithEventsTask->OnCurveRisingEdge.AddDynamic(...);
PlayMontageWithEventsTask->OnCurveFallingEdge.AddDynamic(...);
```

**커브 에지 핸들러**:
- `OnCurveRisingEdgeReceived(FName CurveName)`:
  - EnableBufferInput 상승 → `SetBufferEnabledByServer(true)` (서버만)
  - ActionRecovery 상승 → `AddStateRecoveringTag()` (서버만)

- `OnCurveFallingEdgeReceived(FName CurveName)`:
  - EnableBufferInput 하강 → 아무것도 하지 않음 (ActionRecovery 하강에서 일괄 처리)
  - ActionRecovery 하강 → `DisableBufferAndExecuteOnServer()` 호출

**DisableBufferAndExecuteOnServer() 처리 순서**:
1. `OnActionRecoveryEnd()` 가상 함수 호출 (자식 클래스 오버라이드 가능)
2. 서버 권한 체크 (`HasAuthority()`)
3. `ProcessPendingInputs()` - 대기 입력 처리
4. `ExecuteBufferInternal()` - 버퍼 실행
5. `SetBufferEnabledByServer(false)` - 버퍼 닫기
   (홀드 릴리즈는 Server_BufferInput에서 즉시 처리되므로 별도 처리 불필요)

**OnActionRecoveryEnd() 가상 함수**:
- 기본 구현: `RemoveStateRecoveringTags()`
- 자식 클래스에서 오버라이드하여 추가 로직 구현 가능

**EndAbility() 안전 처리**:
- 어빌리티 종료 시 `RemoveStateRecoveringTags()` 호출 (커브 에지 누락 대비)
- 서버에서 `SetBufferEnabledByServer(false)` 호출 (버퍼 닫기)

#### 3-2. RollAbility 수정
**파일**: `Source/ActionPractice/Public/GAS/Abilities/Player/RollAbility.h/cpp`

**변경 사항**:

## 몽타주 커브 추가 가이드

각 공격/구르기 몽타주에 Float 커브 추가 필요:

```
시간 -->
EnableBufferInput: ____/‾‾‾‾‾‾‾‾\____
ActionRecovery:    ‾‾‾‾‾‾‾‾‾‾‾‾‾\____
                       ^         ^
                   선딜시작   리커버리끝
```

- **EnableBufferInput**: 0→1 (입력 저장 시작), 1→0 (입력 저장 종료)
- **ActionRecovery**: 1→0 (리커버리 종료, 캔슬 가능)
- 커브 이름: `EnableBufferInput`, `ActionRecovery` (FName으로 조회)

## answer.txt 피드백 반영 (2026-01-19)

### 수정된 문제점

#### 1. ProcessPendingHoldReleases 제거
- **문제**: PendingHoldReleases가 선언/함수는 있으나 값이 추가되는 경로 없음 (dead code)
- **해결**: 함수 및 관련 코드 완전 제거
- hold-release는 `Server_BufferInput`에서 수신 즉시 ServerBufferedHoldActionTags에서 제거

#### 2. bIsReleased 의미 유지
- **문제**: 서버 버퍼 경로에서 릴리즈 상태가 ActivateAbility까지 전달되지 않음
- **해결**:
  - `bServerBufferActionReleased` 멤버 추가
  - `BufferInputInternal()`에서 릴리즈 상태 저장
  - `ActivateAbilityByTag()`에서 `bBufferActionReleased = bServerBufferActionReleased`로 반영

#### 3. 기존 GameplayEvent 핸들러 중복 실행 방지
- **문제**: OnEnableBufferInput, OnPlayBuffer 핸들러가 아직 바인딩되어 있어 커브 기반 실행과 중복 가능
- **해결**: BeginPlay에서 이벤트 바인딩 코드 주석 처리
- EndPlay의 핸들러 정리 코드도 제거

#### 4. ResetCombo 노티파이 유지
- **문제**: 계획서에서 OnMontageEnded로 대체 언급됨
- **해결**: 유지하기로 결정 (기존 Charge/Normal 계열 코드에서 사용 중)

### 유지되는 구조

| 항목 | 처리 방식 |
|-----|----------|
| EnableBufferInput | 커브 폴링 |
| ActionRecovery | 커브 폴링 |
| HitDetection | 노티파이 유지 |
| ResetCombo | 노티파이 유지 |
| hold-release | Server_BufferInput에서 즉시 처리 |
