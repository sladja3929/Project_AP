`LockOnComponent` 락온 고도화([[lockon-target-selector-refactor]]) 검수에서 확립된, 카메라 시점을 입력으로 쓰는 타겟팅/조준 계열 기능에 재사용 가능한 체크리스트.

- **로컬 전용 가드는 진입점마다 + 내부 한 번 더(방어적 이중화).** 카메라(`PlayerCameraManager`)가 있어야 계산 가능한 로직은 `IsLocallyControlledOwner()`류 가드를 공개 진입 함수(토글/전환/유지 타이머 시작) 각각에 걸고, 카메라 스냅샷을 만드는 내부 헬퍼에서도 `PC->IsLocalController()`를 한 번 더 확인하는 이중 방어가 정상 패턴. 데디서버·리모트 클라이언트 경로에서 물리 질의/타이머가 절대 돌지 않는지 호출 그래프로 끝까지 추적해서 확인할 것.
- **순수 계산은 별도 비-UObject 클래스로 분리.** 월드/액터/물리에 의존하지 않는 static 함수 모음(좌표 투영, 점수화, 힙/argmin 선택)으로 빼면 Automation Test에서 월드 스폰 없이 바로 검증 가능. 액터 참조가 필요하면 `TWeakObjectPtr`만 들고 계산에는 좌표만 쓰게 한다.
- **탈락(AND) 조건과 선호 점수(가중합)를 분리.** 가시성처럼 자격을 결정하는 조건을 점수에 섞으면 다른 항이 높은 부적격 후보가 이길 수 있음 — 반드시 별도 boolean 게이트로 먼저 걸러낸 후에만 점수 비교.
- **탈락이 있으면 힙(top-k 지연 평가), 탈락이 없는 단일 선택이면 argmin 선형 스캔.** 힙+HeapPop을 쓸 때는 `EAllowShrinking::No`(5.7 시그니처)로 반복 pop 시 재할당 방지, predicate는 UE Heap이 "작은 쪽이 top" 규칙이므로 최고점을 원하면 `A.Score > B.Score`로 뒤집어야 함.
- **사망 처리 멀티캐스트가 사망 태그보다 먼저 온다면, 태그 필터만으로 재선택을 막지 못함.** `Multicast_ReleaseLockOn` 같은 사망 연출 RPC가 `State.Dead` 태그 부착(몽타주 BlendOut 이후)보다 먼저 실행되는 프로젝트라면, 재탐색 함수에 죽어가는 액터를 `ExcludedActor` 파라미터로 명시 전달해야 함. 태그 기반 필터를 믿고 생략하면 다음 프레임에 죽어가는 적이 다시 락온된다.
- **서버 검증 실패 시 클라이언트 낙관적 상태를 강제로 되돌리는 보정 RPC는 선택 사항.** 넣지 않기로 한 경우 클라(시각)-서버(권위) 상태가 갈릴 수 있음을 인지하고, 그 상태를 읽는 다른 시스템(이동 방향, 회전, 전투 판정 등)이 서버 권위 경로에서도 참조되는지 호출부를 추적해 실질적 게임플레이 영향이 있는지 반드시 확인할 것 — 순수 로컬/시각 용도로만 쓰이면 Suggestion, 서버 권위 로직에도 쓰이면 Warning 이상으로 격상.

**Why:** 이런 실수는 "빌드는 되지만 데디서버에서만 크래시/오동작"하거나 "가끔 죽어가는 적이 다시 락온되는" 재현이 어려운 버그로 이어져서, 정적 리뷰 단계에서 호출 그래프를 끝까지 추적하지 않으면 놓치기 쉬움.

**How to apply:** 락온/조준/타겟팅류 기능(AI 타겟 선택, 카메라 락 등) 리팩토링을 검수할 때마다 위 5개 항목을 순서대로 diff에 대조할 것.
