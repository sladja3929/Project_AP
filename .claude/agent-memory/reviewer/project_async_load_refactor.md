- **Phase 3 완료 (2026-07-21 검수 통과):** B그룹 6개 파일(`AttackSequenceAbility.cpp` AttackMontage+SubAttackMontage 2곳, `EnemyAttackAbility.cpp` 1곳, `BlockAbility.cpp` BlockIdleMontage 1곳, `HitReactionAbility.cpp` GuardBreak+BlockReaction계열 5곳, `ParryAbility.cpp` ParryMontage 1곳, `UseItemAbility.cpp` UseMontage+UseMesh 2곳)에서 `LoadSynchronous()` 단독 호출 → `.Get()` + 조건부 동기 폴백(`[AsyncPreload] <위치> ... sync fallback` 로그) 패턴으로 전환. 폴백 조건은 상위에 이미 `!IsNull()` 가드가 있는 분기(HitReaction GuardBreak/BlockReactionHeavy-fallback, Parry, UseItem UseMesh)에서는 `if (!Montage)`만으로 충분(가드가 이미 IsNull==false를 보장), 상위 가드가 없는 분기는 `if (!Montage && !IsNull())`로 명시 — 둘 다 정확. 로드 대상 오탐/누락 없음, 최종 몽타주 포인터 동등성(캐시 히트 시 `.Get()`=기존 `LoadSynchronous()` 반환값과 동일 객체, 미스 시 그 프레임에 동기 폴백으로 동일 객체 확보) 확인. 로그 식별자는 어빌리티명+필드명 접두사와 `ToString()` 경로로 지점별 구분 가능. 제외 대상(BaseAttackAbility/NormalAttackAbility/ChargeAttackAbility 계열은 `AttackSequenceAbility`로 완전 대체된 죽은 경로로 실제 grant/호출부 없음 확인, HitReactionAbility 일반 피격 리액션은 TObjectPtr 캐시 반환이라 애초에 LoadSynchronous 대상 아님, `AbilityTask_PlayNormalAttackMontage`도 생성 호출부 없어 데드코드, UI 텍스처/TitleScreenWidget은 Phase 5/제외 케이스)도 코드로 직접 확인해 타당성 검증 완료. 프로젝트 전체 `.LoadSynchronous()` grep으로 누락 지점 없음 확인.

- **Phase 5 완료 (2026-07-21 검수 통과):** UI 텍스처 비동기화(EquipmentSlotWidget/NotificationEntryWidget) + 서버 분기(UsableItemDataAsset UseMesh 프리로드, UseItemAbility::SpawnItemMesh). EquipmentSlotWidget은 `TMap<UImage*, FSlotIconRequest{Handle, Path}>`로 이미지별 진행 관리, 새 요청 시 `CancelPendingIconLoad`로 이전 핸들 취소 + 콜백 내 Path 기반 세대 검증(이중 방어, `FStreamableHandle::CancelHandle()`이 "지연 콜백 큐에 있어도 완료 콜백을 막는다"는 엔진 보장과 별개로 추가 안전망), `NativeDestruct`에서 TMap 전체 순회 취소. NotificationEntryWidget은 단일 `IconLoadHandle` 멤버 + 재요청 전 취소 + `NativeDestruct` 신설. 둘 다 `CreateLambda`(WeakLambda 아님) + 콜백 진입부에서 `TWeakObjectPtr<위젯>`/`TWeakObjectPtr<UImage>` 수동 `.Get()` null 체크로 파괴된 대상 접근 차단 — UImage까지 두 UObject를 체크해야 해서 단일 UObject만 지원하는 CreateWeakLambda 대신 의도적으로 CreateLambda+수동 체크 사용, 타당함. TMap 키(`UImage*`)는 BindWidget으로 위젯 인스턴스 생존 기간 내내 안정적인 포인터라 stale-key 문제 없음(엔진 `Public/Blueprint/UserWidget.h` 관례상 BindWidget 포인터는 NativeConstruct 시 1회 바인딩 후 고정). AssetManager 미초기화 시 동기 폴백 경로 존재(EquipmentSlotWidget), NotificationEntryWidget은 미초기화 시 Collapsed 처리(디자인 선택, 폴백 없어도 안전하게 숨김 처리라 결함 아님). 서버 분기: `UseMesh`는 `SetCollisionEnabled(NoCollision)` 확인된 순수 시각 요소라 서버 스킵 타당, `ApplyItemEffect()`(GE 적용)와 `ConsumeEquippedItem()`은 `SpawnItemMesh()`와 완전히 분리된 코드 경로라 서버에서 스킵 영향 없음, `UseMontage`는 서버 무조건 프리로드+사용 시점 로드 유지 확인. UI 위젯(EquipmentSlotWidget 등)에 서버 가드 없는 것은 `ActionPracticePlayerController::CreateMasterHUDWidget()`류 함수가 `if (!IsLocalController()) return;`로 가드돼 있어 데디서버에서 위젯 트리 자체가 생성되지 않는 진짜 데드 경로임을 호출 체인 추적으로 확인 — 결함 아님.
